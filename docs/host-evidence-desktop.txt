【判读：三个真实宿主才暴露的问题】
--------------------------------------------------------------------

■ 问题 1 · 模型切换是必须的，不是可选的 ⚠️
20:32 那次失败报 `context window exceeds limit (2013)`。
2013 = MiniMax-**M2.7** 的上下文窗口。这与我此前在 headless 踩的坑**完全同构**
（headless 也报 `CONTEXT_WINDOW_EXCEEDED (2013)`）。
用户在失败后把默认模型从 M2.7 切到 **MiniMax-M3**，20:34 那次就成功了。
→ 再次实证：**M2.7 在此配置下不可用，必须换 M3**。

■ 问题 2 · README「已知缺陷 1：标题质量」在真实宿主上复现了
条目标题字面是 **`T1 <think>`** —— 标题被模型的思维链标签污染。
README 记载「27 代里 13 条标题字面是 `Primary Request and Intent`」，
本次是**同一类缺陷的另一形态**：标题取自模型输出第一行，
而本次模型第一行恰好是 `<think>` 开头。
→ 这条缺陷**不是孤例，而是稳定可复现的**。修法（README「下一步增强点 3」）：
  从该区间首个用户消息确定性取标题，做交叉校验。

■ 问题 3 · `<think>` 正文泄漏进了索引（比 README 描述的更严重）
README 声称「装配器已把叙述正文丢干净（0 / 27 代泄漏）」——
**本次实测反例**：条目里不仅标题是 `<think>`，
**思维链正文也整体进了条目**（`<think>The user said "继续"...`）。
这与 README 的「强制丢弃叙述正文」承诺矛盾。
可能原因：宿主在 continuum 的指导消息**之后**又追加了自己的压缩指令
（README 缺陷 1 的机制描述），模型把思维链写进了被当作条目的位置，
而装配器只按固定标题行切分，没识别 `<think>` 块。

→ **这一条需要向插件作者反馈**：现有单测未覆盖「模型把 <think> 写在
  条目首行」这一形态。
